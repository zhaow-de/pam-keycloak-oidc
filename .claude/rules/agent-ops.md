# Agent operations

- **The commit gate is the ONLY gate — `pre-commit run -a` before claiming done, before pushing, and before opening a PR.** No workflow runs on a pull request, and the only branch-`push` trigger publishes the docs site from `main`, so nothing ever compiles, vets, or tests a branch; a PR with no failing check means nothing was checked. `--no-verify` leaves the change with no check at all; `SKIP=<id>` drops only that hook, and `SKIP=staged-kind` is the one sanctioned use (`commit-messages.md`).
- **Never scope verification down to the files you touched** — the module is one flat `package main`, so `./...` is the whole thing.
- **Never accept `make all` / `make build_all` as evidence that the code compiles** — `build_all` runs `go build` inside `$(shell ...)`, which discards the exit code, so a file that does not parse still prints `All compiled!` and exits 0 with no binary produced — and `$(shell …)` runs at expansion time, so `make -n build_all` is not a dry run either: it cross-compiles all six binaries. Compile-check with `go build ./...`.
- **A `-run` filter that matches nothing still exits 0** — `go test -run <pattern> ./...` prints `ok ... [no tests to run]`; confirm the pattern selects the test under proof before reading its pass as evidence.
- **A guard (test, assertion, check) is unproven until the defect it names is constructed and seen to trip it** — on a fixture where defect and correct behaviour DIFFER; a fixture the defect cannot move passes under the defect and proves nothing. Read WHICH failure fired before recording the result: a red run can be the guard misfiring on a healthy path. Pair it with a **true-positive** — a real, healthy input that must pass — or an always-refusing guard ships green.
- **Assert on what the defect moves, not on the headline** — `err == nil`, an exit code, and `$?` after a pipeline (the last command's status, not the probe's) are routinely identical on both sides of a real defect.
- **A grep hit is not a call site** — open the match and confirm it is a call before claiming X calls Y; a doc comment, a string literal, or a `_test.go` mention proves nothing about production reachability.
- **An empty filtered query is not an absent event** — require a positive trace before concluding nothing happened, and validate the filter first: `gh run list` for a PR or a feature branch returns nothing because no workflow triggers on either, not because checks passed. Print the input's line count and confirm it is non-zero before trusting any zero.
- **A truncated sweep is not a sweep** — piping aggregated evidence through `head`/`tail` before the assertion silently drops the counterexample; bound the input per file, never the evidence stream.
- **A `sed -i` substitution silently no-ops on a missed match** — grep for the new text after every in-place edit; only the Edit tool errors on a miss.
- **Bound every network-touching `git` or `gh` call with the Bash tool's `timeout` parameter, and run it as its own step** — not with a `timeout(1)` shell prefix. Poll a remote with short per-call timeouts rather than one long foreground wait.
- **Never spawn a shell that polls or waits for a background job you started** — the harness re-invokes you when it exits; a genuine wait on external state goes *inside* the one backgrounded command doing the work, never in a second watcher shell.
- **A local ref is not a published ref** — confirm with `git ls-remote --heads origin <branch>` / `--tags` before claiming a branch or tag exists on origin; `release.md` holds the release ritual.
- **`git mv` stages a rename of the INDEX version** — edits made before the move stay unstaged and `git status` shows `R100`; `git add` the new path after every `git mv`, and check invariants against the **committed** tree, never the working tree.
- **Chain history-rewriting git commands one per call, never compounded** — verify each step's effect before issuing the next; `--amend` folds the staged set into HEAD, so read `git log -1 --stat` first.
- **Snapshot an untracked or gitignored file before a tool rewrites it** — git has no undo for it; delete the copy only after the last verification that could read it.
- **A subagent whose final message says it is *waiting* for a backgrounded command is stranded** — its turn ended and the work sits uncommitted. Check `git status`, then resume the **same** agent via SendMessage with numbered foreground steps ending at the commit; never dispatch a fresh twin. A "failed: API error" notification can also be premature — check the tree before re-dispatching.
- **Subagent dispatch prompts say**: run everything as plain blocking commands, background nothing, do not end the turn before the commit exists — and still expect to occasionally resume.
- **Never run two write-capable subagents against this worktree concurrently** — dispatch writers one at a time, or give each its own `git worktree`. Read-only reviewers may run in parallel with each other, but not alongside a writer — and a reviewer permitted to mutate-and-restore is a writer.
- **A number quoted from a subagent's or reviewer's report is unmeasured until you reproduce it** against the source, at full precision.
- **Observed drift is not license** — a committed change that skipped a required step is a finding to flag, never a template to copy.
- **Correct a durable doc by rewriting it in place, never by appending a retraction** — the uncorrected text reads first, and more confidently than the correction below it; the file must read correctly cold.
- **A recorded footgun names the safe alternative in the same sentence** — "don't use X" without "use Y instead" strands the next session at the moment it needs the answer.
